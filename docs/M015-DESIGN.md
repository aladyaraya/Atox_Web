# M015 · 用户项目投稿与官方管理设计

本轮按用户确认开发用户投稿，不提供官方新建或代改作者内容。后台项目管理与活动管理并列；审核通过与公开发布分开。旧公开版本在新稿编辑、送审、审核期间持续展示，官方发布新版才替换。

独立项目不限投稿时间；关联活动必须已报名并按活动原提交期上传／保存／重提，首次送审后固定关联。项目审核不限时，不复用选手材料审核窗口。PDF 可选且仅供审核；公开展示需明确原创、素材授权及公开授权。正文支持中英文其一及可选翻译，缺译回退原文。

作者控制自己的草稿、送审及公开授权。驳回附必填原因，作者可在允许时间修改重提。主动下架立即隐藏并清除当前授权，恢复须重新勾选授权、送审和发布。管理员只读正式版本与附件，不能读取未提交草稿；两类有效管理员均可审核、预览、发布、附原因下架并查看项目业务历史。

现有 12 个演示项目导入同一项目表，保留 ID、内容、时间和互动，没有虚构 owner 或审核历史；只提供预览和上下架。M006/M012 统一查数据库，不回退静态配置；来源和审核／发布状态独立。活动下架隐藏关联公开项目，资料及历史留存，活动恢复不能越过项目自己的下架／授权状态。

草稿修订、不可变送审版本和公开引用分离。共同写协调器内复查权限、资格、版本及文件归属；发布绑定当前批准的版本，实际 SQL 写入检查投稿截止；审核／发布／撤销及审计同事务。通过明确输入 DTO 和公开 DTO 白名单，防止私有材料、账号和 PDF 混入公开展区。

页面、字段、接口、附件标准、错误恢复及数据所有权以 [模块 README](../src/modules/project-submission/README.md) 为完整实施契约。真实数据停服备份再迁移；测试使用独立目录。不改 M002 私有材料来源、M009 时间规则、真实支付或 OIDC 配置，不将本轮视为生产上线。
